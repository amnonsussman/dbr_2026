## 2. שינויים בקוד — dbr_P_01_main.html

### 2.1 מעבר לקובץ מאוחד (V2)

**מה נעשה:** הוספת אלגוריתם דירוג חלופי שקורא מ-`dbr_P_01_data.csv` בלבד במקום מארבעה קבצים (ntm.csv + sm.csv + ntm2026.csv + sm2026.csv).

**משתנים חדשים:**
- `flatDB` — מילון מועמדים מהקובץ המאוחד (מפתח = id1)
- `useV2` — דגל להחלפה בין שיטות

**פונקציות V2 חדשות:**
- `v2TopicScore` — ציון נושא מ-sud/suc/sut, משתמש במשקלי עדיפויות או כיוון
- `v2TopicFit` — התאמה לנושאים שנבחרו
- `v2PublicTone` — סגנון ציבורי מ-zps/zpc
- `v2KnessetRole` — תפקיד בכנסת מ-zr1/zr2/zr3
- `v2CoveredCount` — חישוב נושאים מכוסים (מחליף שדה שלא קיים בקובץ המאוחד)
- `v2InfoTol` — סובלנות חוסר מידע
- `v2ProvenPot` — מוכח מול פוטנציאל מ-zcca
- `v2Loyalty` — נאמנות מפלגתית מ-zcrg0
- `computeScoreV2` — חישוב ציון כולל V2 כולל נאמנות
- `getPriorityWeights` — מחשב משקלים דינמיים לפי סדר לחיצות העדיפויות

**מיפוי שדות ישן→חדש:**

| שדה ישן (עברית) | שדה חדש (מערפל) |
|---|---|
| סגנון | zps |
| סגנון_ביטחון | zpc |
| תפקיד_מאבק | zr1 |
| תפקיד_חקיקה | zr2 |
| תפקיד_חיבור | zr3 |
| ממוצע_עמדות | zcca |
| נושאים_מכוסים | מחושב מכמות שדות מלאים |
| נאמנות מפלגתית | zcrg0 |
| עמדות_ציון/ביטחון לנושא N | sudN / sudNe |
| ביצוע_ציון/ביטחון לנושא N | sucN / sucNe |
| תדמית_ציון/ביטחון לנושא N | sutN / sutNe |

**UI:** כפתור "V2" ירוק במסך הדירוג (s-final) מחליף בין שיטות. השיטה הישנה נשמרת במלואה.

### 2.2 שאלת עדיפויות — "מה חשוב לך במועמד?"

**מה נעשה:** שאלה חדשה במסך s-style עם ארבע אפשרויות סימון (multi-select). סדר הלחיצות = סדר העדיפויות.

**אפשרויות:**
1. שיהיו לו עמדות ברורות בנושאים שחשובים לי (opinions)
2. שיהיה מסוגל לעשות עבודה בכנסת (capability)
3. שייצג את המחנה בצורה טובה בציבור הרחב (image)
4. נאמן למפלגה ולערכיה (loyalty)

**לוגיקה:**
- `state.priorities` — מערך שמור ב-localStorage, שומר סדר לחיצות
- `togglePriority()` — מוסיף/מסיר מהמערך
- `getPriorityWeights()` — מחשב משקלים דינמיים לפי סדר הלחיצות
- שלושת הראשונים (opinions/capability/image) → משפיעים על משקלי הצירים בתוך חישוב הנושאים
- הרביעי (loyalty) → פקטור רוחבי עצמאי שנכנס לחישוב הסופי
- לא סימן כלום → מאוזן (ברירת מחדל)
- **המשקלים ב-getPriorityWeights הם placeholder** — צריך לכייל

**UI:** כפתורים עם מספר סידורי (badge) שמראה את סדר הבחירה.

### 2.4 פיצול מסך השאלות לשני מסכים

**מסך s-squad (שאלות סגל):** שתי שאלות כלליות — סגנון ציבורי + תפקיד בכנסת.
**מסך s-style (שאלות מועמד):** שאלות אישיות — עדיפויות, חוסר מידע, פוטנציאל.

השאלות מה-config מסוננות לפי מפתח:
- `SQUAD_KEYS = ['public_tone', 'knesset_role']`
- `CANDIDATE_KEYS = ['missing_information_tolerance', 'proven_vs_potential']`

### 2.5 מסך סגל — מבנה חדש עם תמונות ושלוש אפשרויות

**מבנה תמונות (s-squad):**
- 12 מקומות בריץ רץ: גבר, אישה, גבר, אישה...
- יאיר גולן באמצע קבוע (68px, מסגרת כחולה)
- משוריינים משתבצים במקום המגדר שלהם עם תמונה אמיתית + שם משפחה
- שאר המקומות — סילואטים אנונימיים (גבר=אפור-כחול, אישה=סגלגל)
- מבנה: 4 למעלה, 2+יאיר+2 באמצע, 4 למטה
- הכל מוקף מסגרת כחולה עם קצוות עגולים

**שלוש אפשרויות (רדיו):**
1. "הסגל הטוב והאיכותי האפשרי" → מסך s-squad-best (ריק, ייבנה)
2. "מה הכוונה, הסבר ופרט" → מסך s-squad-explain (שתי השאלות פתוחות)
3. "אני רוצה לכתוב לך בשפה שלי" → מסך s-squad-custom (ריק, ייבנה)

- לחיצה נוספת על אותו רדיו מבטלת
- כפתור המשך מוחוור כשאין בחירה

**אנימציית תמונות:** קיימת בקוד אבל מושבתת (`startSquadPhotos` מסומן כהערה). אפשר להחזיר.

**GENDER_MAP:** מילון מגדר לכל המועמדים — משמש לשיבוץ ריץ רץ.

**סילואטים:** SVG inline (ANON_M_SVG, ANON_F_SVG) — לא קובץ חיצוני.

## 4. החלטות עיצוב שנקבעו (טרם מומשו)

### 4.1 זרימת מסלול מהיר
- שלושה מסלולים ממסך הסגל: "הטוב ביותר" / "תסביר" / "אכתוב בשפה שלי"
- מסכים חדשים s-squad-best ו-s-squad-custom ריקים — תוכן ייבנה

### 4.2 לוגיקת מספר נושאים
- 4 נושאים ומעלה → משקל שווה בין הנושאים, ללא כיוון פר נושא
- 3 ומטה → שאלת כיוון פר נושא (רק אם בחר "אחליט בהמשך" בשאלת הצירים)

### 4.3 שאלת צירים גלובלית
- הוחלפה בשאלת העדיפויות עם סדר לחיצות
- מי שלא סימן כלום = מאוזן
- מי שרוצה כיוון פר נושא מקבל את זה אם בחר 3 נושאים ומטה

### 4.4 יחס נושאים לרוחביים (היום 80/20)
- צריך להיות פונקציה של כמות הנושאים שנבחרו
- טרם נקבעה עקומה מדויקת

### 4.5 פוטנציאל מול מוכח — חישוב חדש
- מחושב מהפער בין sud (דעות — מה אומר) ל-suc (יכולות — מה עשה)
- מחליף את החישוב הישן שהתבסס על נושאים_מכוסים וממוצע_עמדות

### 4.6 טיפול ב"אין מידע"
- נדחה לשלב הבא
- מוכר כבעיה שצריכה פתרון

### 4.7 בר תחתון להתקדמות
- הוצע להעביר את שלבי ההתקדמות לבר תחתון צמוד
- עם כותרת על קו המסגרת
- טרם מומש
