## שאלה 4 — proven_vs_potential: הבעיה הממשית

```javascript
function sProvenPot(name) {
  const s = sumDB[name];  // ← SM גלובלי בלבד
  const frac = נושאים_מכוסים / 12;       // כמה נושאים מ-12
  const avg  = ממוצע_עמדות;              // ממוצע גלובלי על כל 12 נושאים

  const proven = frac * avg * 12;   // רקורד = כיסוי × עמדות
  const pot    = avg * 10;          // פוטנציאל = עמדות בלבד

  // תשובת המשתמש קובעת את המיקס:
  // proven_safe         → 85% proven + 15% pot
  // balanced            → 55% proven + 45% pot
  // interesting_potential → 25% proven + 75% pot
  // topic_dependent     → 50% proven + 50% pot
}
```

**הבעיה:** גם `frac` וגם `avg` הם גלובליים — ממוצעים על כל 12 הנושאים, ללא קשר לנושאים שהבוחר בחר. אם בחרת נושא אחד שהמועמד חזק בו, הוא עדיין ייענש על כיסוי חלקי בנושאים האחרים.

- מכיל נתונים ברמת נושא — בדיוק מה שצריך לשקלול מותאם אישית

- SM הוא פיבוט מאבד-מידע של NTM — לחזור למקור
